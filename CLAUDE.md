# REGLA PRIORITARIA — NO TOCAR LO QUE YA FUNCIONA

**Antes que cualquier otra instruccion de este archivo.**

1. **No se modifica, mueve ni elimina codigo que ya funciona** para hacer sitio a
   algo nuevo. Si una funcion, un servicio o una ruta esta operativa, se deja
   intacta y lo nuevo se acopla a su lado.
2. **Si un cambio exige tocar algo que funciona, se pregunta antes** y se explica
   por que no hay alternativa. No se decide por el usuario.
3. **Un arreglo no puede empeorar lo que ya iba bien.** Ante la duda entre un
   cambio elegante que toca lo existente y uno feo que no lo toca, gana el que
   no lo toca.
4. **Lo que se toca, se verifica.** Y se dice explicitamente que se toco, por
   que, y como se comprobo que sigue funcionando.
5. **No optimizar para un modelo, workflow o proveedor concreto.** Omni IA Game
   usa muchos modelos y cada usuario trae el suyo. Lo especifico se detecta en
   tiempo de ejecucion y se adapta; no se hornea en el codigo.
6. **Regla de Versionamiento e Instaladores:** Cada vez que se prepare o compile
   un nuevo instalador, se debe verificar la version actual y subirla exactamente
   un punto SemVer (ej: de v0.2.3 a v0.2.4, de v0.2.4 a v0.2.5). Se debe sincronizar
   en TODOS los 8 archivos de version del proyecto:
   - `package.json`
   - `src-tauri/tauri.conf.json`
   - `src-tauri/Cargo.toml`
   - `services/updateService.ts` (`CURRENT_VERSION`)
   - `App.tsx` (fallback updateData y badges de version)
   - `auth-server/public/updates.json`
   - `auth-server/public/index.html`
   - `auth-server/server.js`

Motivo: esta aplicacion lleva mas de un ano en desarrollo y tiene mucho
funcionando. El coste de romper algo estable es mayor que el beneficio de
cualquier mejora.
